多设备的主要维护成本是状态不一致。维护表不应该存密码或完整订阅，只保存能够判断“哪台还需更新”的信息。

## 表中保留这些字段

| 字段 | 用途 |
| --- | --- |
| 自定设备代号 | 避免写公开可识别信息 |
| 系统与客户端版本 | 对照兼容要求 |
| 配置来源类型 | 区分专用账号、订阅及手工配置 |
| 最近更新日期 | 找到可能落后设备 |
| 验证目标与结果 | 证明曾完成实际请求 |
| 私人备份位置说明 | 方便本人恢复，不记录密钥 |

## 更新一台后再处理下一台

先选常用设备，保存原配置，更新并测试。通过后才处理第二台，备用设备在有时间验证时再改。全部一起更新会失去正常参照，也不利于分清服务配置与软件版本问题。

## 将自动更新也纳入记录

自动更新开启不等于最后一次更新成功。检查结果与节点分组，记录错误或停用状态。不同版本可能有不同的更新时间和入口，维护表记录实际状态，不能用“已设置”替代“已验证”。

## 定期删除失效记录

淘汰设备前在应用内停用连接并按服务规则处理会话；订阅疑似泄露应从实际服务入口重置，再逐台替换。表中旧记录标记退役，不公开配置。本文没有确认零点云具体设备数量。[订阅安全](/tutorials/subscription-safety/)介绍迁移保密原则。
